# `chrome/browser/ui/side_panel/` — side-panel entries, actions, prefs

> Part of [`../AGENTS.md`](../AGENTS.md) (`chrome/browser/ui/`) in
> [`packages/browseros/`](../../../../../AGENTS.md).

## What's here

The browser-layer (non-views) side of the side panel: the entry-ID
registry, the profile prefs for BrowserOS panel state, and the toolbar
action callback that toggles a pinned BrowserOS extension's contextual
panel.

## Rules

**SP1 — Entry IDs are generated by the `V(...)` macro.** The macro takes
(enum name, action id, string). The string form is what appears in prefs and
in `SidePanelEntry::Key`; changing it orphans saved state.

**SP2 — Every panel pref here is `browseros.`-prefixed and
feature-gated.** `kThirdPartyLlmProvidersPref` and friends are only
registered inside `if (base::FeatureList::IsEnabled(...))` blocks. Code that
reads them must check the same flag — with the flag off, the pref does not
exist and `GetList()` returns null.

**SP3 — `kClashOfGptsPaneCountPref` defaults to 3.** This is the
`kDefaultClashOfGptsPaneCount` constant in the anonymous namespace at the
top of the file. Change the constant, not the registration site.

**SP4 — The toolbar callback is for BrowserOS extensions only.**
`CreateBrowserosToggleSidePanelActionCallback` is bound for actions whose
extension satisfies `browseros::IsBrowserOSPinnedExtension()`. It resolves
the *active* tab's `WebContents` before toggling — there is no
cross-tab behaviour here.

**SP5 — Keep the `browseros:` log prefix.** These `LOG(INFO)` lines are
how BrowserOS toolbar behaviour is diagnosed in the field; the
`browseros: ` prefix is a grep anchor.

**SP6 — Entry registration happens in the views layer.** This directory
declares IDs and prefs; `browser/ui/views/side_panel/side_panel_helper.cc`
calls `CreateAndRegisterEntry` on the coordinators.

## Workflows

**Adding a panel state pref**
1. Add the `constexpr char k…Pref[]` constant in the anonymous namespace of
   `side_panel_prefs.cc` with a `browseros.` prefix.
2. Register it in the matching `FeatureList` block.
3. Read it only behind the same `FeatureList` check.

**Wiring a pinned extension's toolbar button to its panel**
1. Use `CreateBrowserosToggleSidePanelActionCallback(extension_id, bwi)`.
2. It calls `ToggleContextualExtensionSidePanel` from
   [`../extensions/AGENTS.md`](../extensions/AGENTS.md), which auto-registers
   a contextual entry if none exists.
3. Add the extension to the pinned set in
   `chrome/browser/browseros/core/browseros_constants.h`.

**Adding a new side-panel entry**
1. Add a `V(...)` row in `side_panel_entry_id.h` with its action ID.
2. Declare the action in `../actions/chrome_action_id.h`.
3. Add a coordinator under `../views/side_panel/<name>/`.
4. Construct it in
   `../browser_window/internal/browser_window_features.cc` behind a
   `FeatureList` guard.
5. Register it in `../views/side_panel/side_panel_helper.cc`.
