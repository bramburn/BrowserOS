# `media/` — extension media access for BrowserOS extensions

> Part of [`../AGENTS.md`](../AGENTS.md) (`chrome/browser/`) in
> [`packages/browseros/`](../../../../AGENTS.md).

## What's here

One file, three hunks, all about `ExtensionMediaAccessHandler`. The upstream
allowlist `IsMediaRequestAllowedForExtension()` is a hard-coded list of
component extension IDs (keyboard extension, XKB, M17n/T13n/CJK input methods,
the Accessibility Common extension) that bypass the normal permission prompt
pending crbug.com/40333126. The patch appends item 9 — "BrowserOS extensions
(AI Side Panel and Bug Reporter)" — by delegating to
`browseros::IsBrowserOSExtension()` — and adds a second rule that lets those
extensions capture **audio only** (device audio capture, no video), described
in the code as being for the side panel's teach mode.

## Rules

**MED1 — The allowlist entry is derived, never enumerated.**
`browseros::IsBrowserOSExtension(extension->id())` is the only test. Adding a
BrowserOS extension to
`../browseros/core/browseros_constants.h:kBrowserOSExtensions[]` grants media
access automatically; nothing in this directory changes.

**MED2 — Audio-only is a restriction, not a grant.** The new code *narrows*
`audio_allowed` to exactly
`blink::mojom::MediaStreamType::DEVICE_AUDIO_CAPTURE` for BrowserOS
extensions. Widening it to include video, or treating it as an "allow all"
branch, is a permissions change with a real privacy consequence.

**MED3 — Video capture is unchanged.** `video_allowed` is still computed from
`GetDevicePolicy(profile, extension->url(), prefs::kVideoCaptureAllowed,
prefs::kVideoCaptureAllowedUrls)`. Do not fold the BrowserOS branch into
`video_allowed`.

**MED4 — Keep the numbered comment list in sync.** The upstream block numbers
each allowlist entry and cites crbug.com/40333126. The patch adds
`// 9. BrowserOS extensions (AI Side Panel and Bug Reporter)`. If the
allowlist is ever rebuilt, the numbering must be restored.

**MED5 — The include is `chrome/browser/browseros/core/browseros_constants.h`,
not the server or extensions headers.** The media layer has no dependency on
`//chrome/browser/browseros/extensions`; keep it that way.

## Workflows

**Granting a new BrowserOS extension media access**
1. Do not edit this file.
2. Add the ID to `kBrowserOSExtensions[]` in
   `../browseros/core/browseros_constants.h`.
3. Confirm the extension is one whose *only* needed capture is audio; if it
   needs video this file will have to change deliberately, with a review.

**Changing what BrowserOS extensions may capture**
1. Edit the `IsBrowserOSExtension` branch in `HandleRequest()`.
2. Keep the device-policy path intact for `video_allowed` (MED3).
3. Re-extract; the patch is three small hunks, so keep it that way.
