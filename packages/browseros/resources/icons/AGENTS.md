# `resources/icons/` — every product and platform icon

> Part of [`../AGENTS.md`](../AGENTS.md) in
> [`packages/browseros/`](../AGENTS.md).

## What's here

The generated icon tree. A single master source (`product_logo_1024.png` +
`product_logo.svg` + `product_logo.ai`) is expanded by
`build/scripts/icon_generation/generate_icons.py` into the flat size
ladder, the per-OS subdirectories, the Windows `.ico` set, the Linux `.xpm`,
the macOS `.icns` / `Assets.car` / `Assets.xcassets` bundle, and the two
DPI-scaled trees.

Nothing here is chosen by convention — every copy is declared in
`build/config/copy_resources.yaml`, either as a flat glob
(`resources/icons/*.png`, `*.ai`, `*.svg`) or as a whole-directory
`type: directory` entry per platform.

## Rules

**IC1 — Do not hand-edit any binary here.** Everything is generated by
`build/scripts/icon_generation/generate_icons.py` from `source/app_icon.png`
and the `static/` masters, driven by `generate_icons.txt`. Hand edits are
lost on the next regeneration with no diff warning.

**IC2 — `.ai` files are 0 bytes on purpose.** `chromium.ai` and
`product_logo.ai` exist so the `resources/icons/*.ai` copy glob matches.
The real vector source is `product_logo.svg`.

**IC3 — Filenames are load-bearing.** Chromium's theme code looks up
`product_logo_<size>.png`, `product_logo_name_22.png` and
`product_logo_name_22_white.png` by exact name at the exact DPI-directory
level. A renamed file becomes an invisible blank icon, not a build error.

**IC4 — `default_100_percent` and `default_200_percent` are separate
trees, not scale factors of each other.** They are copied to *sibling*
Chromium directories (`chrome/app/theme/default_100_percent/chromium` and
`.../default_200_percent/chromium`). The 200 % tree holds 2x pixel sizes at
the same nominal size (e.g. `product_logo_name_22.png` at 1x is 1081 bytes in
the 100 % tree and 2432 bytes in the 200 % tree).

**IC5 — `default_100_percent/linux/` has no 200 % counterpart.** It is
covered by the `default_100_percent` directory copy; adding a
`default_200_percent/linux/` subdirectory would work automatically but no
generator rule produces one today.

**IC6 — `mac/Assets.car` and `mac/app.icns` are referenced by name from
outside this tree.** `chromium_files/chrome/updater/branding.gni` sets
`updater_app_icon_path = "//chrome/app/theme/chromium/mac/app.icns"`.
Renaming that file breaks the updater bundle.

**IC7 — The macOS `.icns` set is generated on macOS only** (`iconutil`,
`actool`). Regenerating the tree from Windows or Linux will not refresh
`app.icns`, `AppIcon.icns`, `document.icns` or `Assets.car` — those need a
macOS host.

**IC8 — `product_logo_1024.png` is the master; the rest are derived.** If
you change the artwork, change the source and regenerate, rather than
patching `product_logo_256.png` alone.

## Workflows

**Changing the app icon**
1. Replace `source/app_icon.png` (≥1024×1024) in
   `build/scripts/icon_generation/source/`, and any static vectors in
   `static/`.
2. Run `python build/scripts/icon_generation/generate_icons.py` (macOS host
   for `.icns` / `Assets.car`).
3. Review the diff in this tree — every size should change together.
4. Re-run `browseros build -m resources` to push them into the Chromium tree.

**Adding a single new size**
1. Add a `PNG <source> <size> <dest>` line to
   `build/scripts/icon_generation/generate_icons.txt`.
2. Regenerate. Adding the PNG by hand without the config line means the next
   regeneration deletes it.

**Adding a new platform icon directory**
1. Create the subdirectory here.
2. Add a `type: directory` entry to
   [`../../build/config/copy_resources.yaml`](../../build/config/copy_resources.yaml)
   with the `chrome/app/theme/chromium/<platform>` destination and any
   `os:` / `arch:` filters.
