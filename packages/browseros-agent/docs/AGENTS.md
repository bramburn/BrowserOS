# `docs/` — package documentation

> Part of [`../AGENTS.md`](../AGENTS.md) in `packages/browseros-agent`.

## What's here

Two hand-written reference documents plus a planning-document folder. This is
the **package's own** docs directory — separate from the repo-root `docs/`
(which holds `MCP_TOOL_SPEC.md` and `CI_AND_RELEASES.md`) and from the
rendered Docusaurus site in `docs-site/`.

- [`events.md`](events.md) — the analytics catalogue: every PostHog event across
  the three emitters, with per-event properties and the global property set.
- [`tool-reference.md`](tool-reference.md) — **auto-generated**; do not hand-edit.
- [`plans/`](plans/AGENTS.md) — dated design + implementation plans.

## Rules

**DC1 — `tool-reference.md` is generated.** Line 1 reads
`<!-- AUTO GENERATED DO NOT EDIT - run 'npm run docs' to update-->`. The
generator is [`../scripts/generate-docs.ts`](../scripts/generate-docs.ts), which
connects to the built MCP server over stdio (`build/src/index.js`), reads the
tool list, and writes `./docs/tool-reference.md` (it also rewrites a
cross-link TOC in `README.md`). Edit the generator or the tools, never the
output.

**DC2 — The `npm run docs` instruction in the banner is stale.** There is no
`docs` script in [`../package.json`](../package.json). Run
`bun scripts/generate-docs.ts` instead — and note it needs a built server,
since it imports `build/src/cli` and `build/src/tools/categories`. Keep this
in mind before following any generated instruction here.

**DC3 — The tool names in `tool-reference.md` are *not* the server's tool
names.** That file is the **Chrome DevTools MCP** surface
(`click`, `navigate_page`, `take_snapshot`, `emulate_cpu`, …) grouped as
Input automation / Navigation automation / Emulation / Performance / Network /
Debugging. The BrowserOS server's own tools are `snapshot`, `dom`,
`navigation`, `act`, `history`, … in
`../apps/server/src/tools/registry.ts`. Cross-referencing the two is a common
mistake; use [`../apps/server/AGENTS.md`](../apps/server/AGENTS.md) for the
real registry.

**DC4 — `events.md` is the source of truth for event naming.** Three prefixes,
and they map to three different emitters: `browseros.server.*` (via
`metrics.log()` in the MCP/HTTP server), `browseros.native.extension.*` (via
`track()` in the extension), and `browseros.native.*` (from the Chromium
browser process). New events must join the right table and use the right
prefix.

**DC5 — `events.md` is hand-maintained and drifts.** It is documentation, not
code — nothing verifies it against the emitters. When you add or change an
event, update this file in the same change.

**DC6 — Don't add build/CI documentation here.** That belongs at the repo
root (`docs/CI_AND_RELEASES.md`) or in `AGENTS-build.md`. This folder is
package-scoped.

## Workflows

**Adding an analytics event**
1. Emit it from the right place: `metrics.log()` in `apps/server/`, `track()`
   in `apps/agent/`, or the Chromium side.
2. Add a row to the matching table in [`events.md`](events.md) with its
   properties.
3. Note that `client_id`, `install_id`, `browseros_version`,
   `chromium_version`, `server_version` are attached to **all** server events
   automatically — do not re-declare them per event.

**Regenerating the tool reference**
1. Build the server first (the generator imports from `build/`).
2. `bun scripts/generate-docs.ts` from `packages/browseros-agent`.
3. Review the diff — it also updates the README TOC.

**Finding the right doc for a topic**
1. MCP tool behaviour in this server → `../apps/server/AGENTS.md`.
2. Chrome DevTools MCP tool parameters → [`tool-reference.md`](tool-reference.md).
3. Port-9200 protocol schemas → repo root `docs/MCP_TOOL_SPEC.md`.
4. Feature history and rationale → [`plans/`](plans/AGENTS.md).
